## Algorithm in plain words
1. **Adapter (725).** Reads the store and works out the family head's age in whole years (age is set only when familyHead exists and has a birthDate). It builds a list of the user's documents (nid, passport, housing, driving, vehicle, ration). Each document is marked valid when its expiry date is later than now. The adapter returns {userAge, governorate, district, documents, services: INITIAL_SERVICES}.
2. **Graph build (726).** For each document it adds a DOCUMENT node `doc_<type>`, plus a DEADLINE node `deadline_<type>` with an edge from the deadline to the document (TEMPORAL_SEQUENCE). For each service it adds a SERVICE node `service_<id>`. Each required-document text is mapped by keywords to a type, and for that type it adds the edges doc_<type>→service (DOCUMENTARY_DEPENDENCY) and deadline_<type>→service (CAUSAL_INFLUENCE). addEdge silently drops an edge when either end node is missing, so these edges exist only for documents the user has entered. Each eligibility condition becomes a node `cond_<id>_<i>` with an edge to the service. If the condition text contains 'سن' or 'عمر' and a number, that number becomes `ageRequirement`, and isValid = userAge >= ageRequirement.
3. **PathFinder (728).** Starting from the target service it searches backwards. For every *present but invalid* DOCUMENT feeding a service, it adds every "producer" service of that document (from DOCUMENT_PRODUCERS) as a prerequisite, then recurses into those producers. A DFS topological sort puts prerequisites first. From that order it emits 2–3 paths: `<target>_digital_first` (each step uses the digital channel when the service has an onlineLink), `<target>_in_person`, and, only when there are more than 2 steps, `<target>_alternative`. The alternative swaps the first two steps when they have no direct edge and neither is the target. Otherwise it reverses every step before the target, using the digital-step map. Each step's duration = STEP_DURATION_ESTIMATES[id] (or default 3) + wait (5 when bookingRequired && channel==='digital', else 2). Its probability is fixed at 0.95, and requiredDocs = labels of the incoming DOCUMENT nodes.
4. **ConstraintSolver (728).** Each path is checked in order: (i) detectCycleInPath; (ii) any incoming ELIGIBILITY_CONDITION with isValid===false; (iii) a walk through the steps that keeps a running day offset from startDate. A required document must be valid or already "renewed" by an earlier step (getProducedDocuments). A valid, not-renewed document fails when the projected execution date is after its expiry. The solver returns {path, score:0, metrics:zeros, isValid, reason, decisionExplanationLog}.
5. **PathSimulator (730).** Each path gets these metrics: expectedTime = Σduration; acceptanceProbability = Πprobability; delayRisk = 0 when no document has an expiry date, otherwise 1 when expectedTime > minSlack, otherwise expectedTime/(minSlack+1), where minSlack = the smallest number of days to any document's expiry, floored at 0; docCount = number of unique requiredDocs labels; crossImpact = number of nodes a BFS (depth 3, outgoing edges) reaches from the step services. Time, docCount and crossImpact are min-max normalised over all paths, invalid ones included. score = clamp01(0.25·P + 0.25·(1−t) + 0.2·(1−risk) + 0.15·(1−docs) + 0.15·(1−impact)), and invalid paths get 0. The paths are sorted in place: valid first, then by score descending.
   calculateConfidence = round(100·(0.25·completeness + 0.25·mean(verificationScore/100) + 0.2·validDocShare + 0.15·(isValid?1:0) + 0.15·mean(exp(−0.001·daysSinceVerified)))) over the step services plus all their incoming source nodes. It returns 0 when there are no nodes.

## (e) Bugs / suspicious behaviour (left in the code on purpose)
1. **Self-cycle makes every renewal path infeasible** (solver.js detectCycleInPath, decompiled ~280210–280330). moi_renew_passport requires 'الجواز السابق الأصلي…' → doc_passport, and doc_passport's producers include service_moi_renew_passport itself. So dfs(renew)→doc_passport→renew is already on the recursion stack → "cycle". The check also ignores whether the document is valid. Result: whenever the user has entered a passport, every passport-renewal path is rejected with 'فشل: حلقة اعتماد دائرية.' The smoke test confirmed this. update_nid (requires NID), and probably renew driving licence and vehicle renewal, behave the same way. Renewal only "works" when the user has never entered the document.
2. **Cycle in resolveDependencies.** generatePaths pushes the self-edge {from: update_nid, to: update_nid} when the target needs its own expired doc. topologicalSort's `visiting` guard ignores back-edges silently, so the code does not loop forever, but cycles are never reported there.
3. **Both producers are added.** For an invalid NID the path contains BOTH 'issue NID first time' AND 'update NID' (and the same for passport: issue + renew). These are mutually exclusive in real life, the expected time doubles, and with the self-cycle the path always fails. Smoke test: renew passport + expired NID → 3 steps, 42 days, all invalid.
4. **Digital is slower than in-person.** createStep adds appointment_needed (5 days) when bookingRequired && digital, and only normal_wait (2) otherwise. So the "digital-first" path always has expectedTime ≥ in-person (smoke test: 42 vs 33). This looks inverted.
5. **Missing documents are never detected.** addEdge drops edges whose source node does not exist. A user who has no NID/passport entered gets no doc edges, so there are no dependencies, no "missing document" failure, and no cycle. Only documents that are *present but expired* create prerequisites. `missingDocs` is collected and never used.
6. **crossImpact is always 0** (simulator.js). Every edge points INTO services (doc→service, deadline→service, cond→service, deadline→doc), and bfs follows outgoing edges, so a BFS from a service reaches nothing. The 0.15 weight is a constant 0.15 bonus, because norm returns 0 when min===max. The bfs visitor also gets called for the start node and filters it out.
7. **Minors always fail passport issue.** The age heuristic matches 'سن' as a substring: the condition 'موافقة ولي الأمر للقاصرين دون سن 18 عاماً' (guardian consent for minors) becomes ageRequirement 18, so every minor fails moi_issue_passport even though the rule only asks for guardian consent. 'سن' also matches words like 'حسن', 'سنة', 'سنوات', 'السنوية'.
8. **Age only applies to the family head.** userAge stays undefined when familyHead is missing or has no birthDate. Age checks are then skipped, so the condition counts as valid.
9. **Invalid Date / NaN risk.** solveConstraints, simulateAndRank and calculateConfidence all do `new Date(arg)`. If a caller passes undefined, the dates become Invalid, comparisons become false, recency becomes NaN, and the confidence is NaN. Also `new Date('YYYY-MM-DD')` is UTC midnight while `today` in the adapter is local time, so there are off-by-one-day edge cases around the expiry date in Iraq (UTC+3).
10. **Normalisation includes invalid paths.** Min/max are taken over all paths, so invalid paths skew the normalised scores of the valid ones.
11. **Division by zero handled.** norm guards max===min; delayRisk uses (minSlack+1); the completeness, reliability, validity and recency averages all guard count>0. No division-by-zero found. Expired documents have slack 0, which gives delayRisk 1 whenever expectedTime > 0.
12. **Mutation.** simulateAndRank mutates the solver's result objects (`metrics`, `score`) and sorts the input array in place. addNode stores a shallow copy, but the steps arrays are shared between the digital_first and alternative paths (the same step objects from digitalSteps).
13. **Alternative path can break dependency order.** The "reverse prefix" branch reverses all prerequisites. Since the target is always last in topological order, this branch always runs when the first two steps are linked, and it can put a dependent step before its prerequisite. Its steps come from the digital map, and it is labelled 'mixed'.
14. **Duplicate edges.** addEdge stores edge objects in a Set (identity), so calling it twice adds duplicate edges. `causal_impact_<svc>_<type>` is computed and never used (dead code). `HORIZON_WINDOW_DAYS`, `missing_required_docs` and the other probabilities are unused; probability is always 0.95.
15. **Crash risk.** build() calls `service.required_documents.forEach` and `service.eligibility_conditions.forEach` without guards, so it crashes if a service lacks either array. createStep's `.filter(n => n.type…)` would crash on a dangling edge after removeNode (removeNode is never called in the engine).
16. **Admin edits are ignored.** mapStoreStateToInput always uses the static INITIAL_SERVICES, not any services list in the store, so admin-edited services never reach the engine.
17. **No producers for housing/ration.** doc_housing and doc_ration have no producer services in DOCUMENT_PRODUCERS. An expired housing card therefore makes every path that needs it fail with 'مستند مفقود/غير صالح بدون خطوة تجديد'.
18. **Odd keyword mapping.** mapDocumentTextToType runs toLowerCase on Arabic, which does nothing. 'تأييد سكن' (residence confirmation) maps to housing, and 'هوية الأحوال المدنية وشهادة الجنسية' maps to nid.
